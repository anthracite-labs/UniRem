- (note) Research: AppT (closest analogue, shipping Samsung TV remote) ships exactly two modules :app + :samsung; its accepted architecture explicitly forbids a forest of domain/data/usecase/repository/per-feature modules and defers universal TV abstraction until a second ecosystem exists.
- (note) Research: Findroid 10 modules split by separate artifacts (phone app, TV app, player, setup); Home Assistant Android 8 modules of which only :app + :common are the product, the rest are other form factors and build infrastructure; Now in Android 40+ modules is an explicit modularization teaching sample, not a product shape.
- (assumption) A build-logic included build and a design-system module are deferred: with four modules the convention-plugin payoff does not clear the YAGNI bar; revisit at six or more modules.
- (decision) Module shape: four Gradle modules, acyclic — :app, :core, :tv, :cast. :app -> :tv, :cast, :core; :tv -> :core; :cast -> :core. :core is pure Kotlin with no Android dependency and owns the capability resolver plus command-outcome types and reducer. Prevents per-feature module sprawl and keeps OKHttp/WS/KEY_* strings and jUPnP/Jetty out of the UI module.
- (decision) Paradigm: deep modular monolith — ports only at the two protocol edges (TvControl, RendererGateway); no separate :domain or :data layer, no usecase layer, no universal-TV abstraction until a second ecosystem exists.
- (assumption) Stack is the Android paved path (Compose, Hilt, Room, DataStore, OkHttp, Navigation Compose, kotlinx.serialization, jUPnP 3.0.5); versions still to be pinned and web-verified before the Stack table is written.
- (note) Research: Matrix EventStatus is error/sending/sent/synced where sent = HTTP request successful and synced = event came back through the sync loop; Signal uses Sending/Sent/Delivered/Read. Both model acknowledgement as an ordered state on the item, not as a general reducer or state-machine framework. The two-stage split is the same distinction as UniRem submitted vs observed.
- (decision) Command truth (revised after research): one small CommandTracker owned by :tv, exposing StateFlow<CommandOutcome>. Adapters emit typed evidence with provenance (TvEvent, StateProbe, UserConfirmed); the tracker holds the current generation, ignores stale evidence, and applies an injected timeout policy. No reducer framework, no MVI library, no event bus, and no tracker in :core.
- (decision) Cast transport and wake do not use CommandTracker: UPnP SOAP is request/response with a real ack, and wake is a one-shot probe with a timeout. Forcing all three into one truth machine is rejected as over-abstraction.
- (decision) Gesture boundary is a caller rule, not a state machine: exactly one submit() per user gesture. D-pad repeat frames send Press/Release without calling submit, so hold-to-repeat cannot strobe the ring.
- (constraint) Three clocks must never merge: command outcome (per gesture, 3s default timeout, injected policy), connection health (backoff, topbar dot), and session lifetime (cast/mirror FGS). Separate types and separate owners.
- (assumption) Timeout is injected policy: 3s default from UX, per-capability override allowed (power-off may never observe, text may exceed 3s). Threshold lives in one place and is validated in Spike A.
- (note) Research: KDE Connect declares incoming/outgoingCapabilities in its identity packet and explicitly notes the list is only an indication the device can consume a type, not that it will; MousePad carries optional sendAck/isAck for per-request confirmation. Home Assistant publishes supported_features as an EntityFeature enum per entity at runtime. AppT states a connected TV is the source of truth for demonstrated capabilities and warns against assuming from model/year tables.
- (decision) Capability resolution splits by whether the device declares the surface. Declared surfaces (UPnP service/action list, TokenAuthSupport, IME events) are authoritative per unit and are not duplicated in the matrix. Silent surfaces (key support, pointer follow, wake) have no declaration, so the verified matrix grants and a per-unit probe may only demote. User confirmation changes command state, never a capability label.
- (decision) Capability precedence ladder, deterministic and evaluated in order: (1) device declares the service absent -> Not supported; (2) probe hard-fails on this unit -> Not supported for this unit; (3) matrix pass and no contradicting probe -> Works; (4) matrix partial/ambiguous or H/J set -> Best-effort; (5) no matrix row and no probe -> Not tested. User confirmation is out of band.
- (decision) Session ownership: cast and mirror session owners are process-scoped and live outside navigation; switching TVs or leaving a screen must not stop them. The remote socket is deliberately the opposite — UI-scoped and closed on background. One FGS per user-started cast or mirror session acts as a lifecycle adapter, not as the session owner.
- (assumption) The process-scoped session owner dies on process death and does not restart silently; the next launch reports the session as ended. This matches the UX rule that a force-stop is never presented as survival.
- (decision) Cleartext policy: network-security-config permits cleartext, and one OkHttp interceptor rejects any host that is not RFC1918 or link-local before the request leaves; jUPnP's HTTP client gets the same check. The manifest exception is named and justified in the spine rather than hidden behind a socket-factory bypass. Prevents a permissive config becoming an open egress path.
- (decision) Verification matrix is a build artifact, not a spreadsheet: versioned data in-repo keyed by model + firmware + network type, consumed by the capability resolver, with a debug harness that records observed-effect rows. The release gate must be readable by the code that makes the claim.
