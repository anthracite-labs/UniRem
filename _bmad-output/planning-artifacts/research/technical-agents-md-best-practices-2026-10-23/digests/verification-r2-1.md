## Secrets guidance
- **No primary vendor guidance was found that explicitly says whether credentials/secrets may appear in AGENTS.md or CLAUDE.md.** GitHub's repository-custom-instructions docs and Anthropic's Claude Code memory docs contain no such statement. The GitHub `/init` prompt only says "Instructions must be no longer than 2 pages". Anthropic only says to keep files short and use hooks for enforcement. (OpenAI/Codex docs were not fetched for this question — see Gaps.)
- What the primary sources do support instead: Anthropic explicitly says instruction files are "context, not enforced configuration" and that blocking must use a `PreToolUse` hook or permissions; GitHub's own docs give no enforcement guarantee. The strongest adjacent evidence is **arXiv:2608.23550**, "When 'Do Not' Is Not Deny": across 481 public CLAUDE.md files, "only about 4-16% of the retrieved security rules had a matching built-in control. Under the strictest standard the estimate was 4.4% (95% CI: 2.6-6.7%)"; "CLAUDE.md is a write-only channel. A developer writes a security rule but gets no feedback on whether a control will enforce it."
- Practical implication (synthesis, not a vendor quote): never place credentials in a committed instruction file. Use a secret manager / CI secrets / environment variables, keep personal instruction files gitignored (`CLAUDE.local.md` is Anthropic's pattern), and enforce "no secret access/commit" with permission `deny`, hooks, sandboxing, and secret scanning — not with a natural-language "do not". Because the file is committed and loaded every session, any credential in it is both in git history and sent to the model provider on every turn.
- No security advisory specifically about secrets in AGENTS.md/CLAUDE.md was found in the sources checked.

## Android-specific evidence
- **No Android/Kotlin/Gradle-specific empirical study of agent instruction files was found.** The targeted search returned none. This is an absence within search scope, not proof of nonexistence.
- Closest adjacent evidence: **"On the Adoption of AI Coding Agents in Open-source Android and iOS Development"** (MSR 2026, https://dl.acm.org/doi/abs/10.1145/3793302.3793596) — 2,901 AI-authored PRs across 193 verified Android/iOS repos; Android acceptance 71% vs iOS 63%; build/refactor tasks succeed less. This is about agent-generated PRs, **not** instruction files or Gradle. Also adjacent: content studies such as "Agent READMEs" (2,303 files/1,925 repos) and "Context Engineering for AI Agents" (466 repos, only 36 Java), neither Android/Kotlin-specific.

## Corrections the report must make

1. Do not attribute the "does not generally improve" wording to v2 — only v1 and v3 were verified; v2 was not read.
2. Do not summarize 2605 as a flat "no effect": size and conflict are affirmative nulls (BF10 0.05–0.10); position and architecture are failures to reject, with ~6pp sensitivity.
3. Do not describe Vercel's n as "small" or the 100% as "a single run" — the post simply does not say. It is a vendor-reported final aggregate.
4. Keep absolute percentage points and relative percentages separate. The ETH intro's "7% on average" for Dev vs LLM is relative to a ~60% base; §4.2's "+2.4%" is absolute points vs None. They are not additive.
5. State that developer-written files were tested only on CTXbench (138 instances/12 repos) and that +2.4 vs None is n.s. (p=0.21); the significant contrast is Dev vs LLM (p=0.038).
6. The 24–2,003-word range is the CTXbench developer-file range and the length result is correlational, not a controlled manipulation.
7. Add the ETH paper's own qualifier: when all documentation files are removed, "LLM-generated context files not only consistently improve performance by 2.7% on average, but also outperform developer-written ones across settings" (Appendix B, Figure 12). The null is conditional on documentation already being present; the paper calls context files "redundant documentation."
8. Anthropic's 200 lines is a "target", not a hard limit.
9. Vercel tests framework-API knowledge delivery, not the general value of AGENTS.md; the winning condition bundles an 8KB index, on-disk docs, and a retrieval instruction.
10. The GitHub "six core areas" claim remains unverified; only the blog's title and 2,500+ corpus are corroborated (via the ETH reference).
